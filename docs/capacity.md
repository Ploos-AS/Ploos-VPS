# Capacity management

The initial pure Go scheduler checks positive requested vCPU, RAM MiB and disk GiB against enabled node inventory, subtracting host reserves and existing allocations. No CPU, RAM or disk overcommit is assumed. Selection favors available RAM and uses node ID for deterministic ties. Callers must supply only eligible nodes for the requested site, cluster, image and network. Inventory must include pending reservations, not just running VMs. This is a planning function, not an atomic reservation mechanism: concurrent requests must be serialized through database transactions before provisioning. Persistent inventory, reservation expiry and reconciliation, N+1 failure-domain capacity, storage IOPS and network constraints remain future work. Do not use this function alone to admit production workloads.
